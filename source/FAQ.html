Category 01

Product & Architecture

What is Workprint?

Workprint is a cross-platform engineering capacity intelligence application built natively on the Atlassian Forge Cloud platform. It aggregates live data across Jira Software (tasks, time spent, remaining estimates), Confluence (technical specs and active page edits), and Bitbucket Cloud (pull request review lag and code contributor activity) to give engineering leads, scrum masters, and developers authentic workload clarity.

How does Workprint differ from traditional Jira reporting?

Traditional Jira reports only measure assigned issues on a specific board. They ignore the substantial hours developers spend conducting pull request reviews in Bitbucket or authoring architecture design specifications in Confluence. Workprint synthesizes all three surfaces into a unified 40-hour weekly sprint capacity model.

Category 02

Installation & Forge Deployment

How do I install Workprint on my Atlassian site?

Site administrators can install Workprint directly from the Atlassian Marketplace or via the Atlassian Forge CLI:

forge install --site workprint.atlassian.net --product jira

Because Workprint includes both Jira and Confluence global page modules, installing to either product enables the cross-tool capabilities.

Why does Workprint request api.asApp() scopes?

Workprint uses api.asApp() to execute Jira and Confluence REST queries with app-level permissions. This allows engineering managers and team leads to generate squad-wide bandwidth reports without requiring every individual engineer on the team to perform manual OAuth consent dances.

Category 03

Bitbucket Cloud OAuth & Repository Token

How does Workprint connect to Bitbucket?

Workprint queries the Bitbucket Cloud REST API v2 (https://api.bitbucket.org/2.0) via backend external fetch. Authentication is handled using a workspace-level Repository Access Token configured with read-only pull request access (read:pullrequest).

Does Workprint inspect or copy our proprietary source code?

No. Workprint never downloads, analyzes, or stores your source code or diff contents. The application only queries PR metadata: author, designated reviewers, state (OPEN), and creation timestamps to calculate review turnaround lag.

Category 04

Atlassian Rovo AI Capacity Agent

How do I interact with the Workprint Capacity Agent in Rovo?

Open Atlassian Rovo chat anywhere in Jira, Confluence, or your browser extension and @mention Workprint Capacity Agent. You can ask queries such as:

  • "Summarize developer workload for Alex Chen."
  • "Who has available bandwidth on our engineering team?"
  • "Are there any PR review bottlenecks blocking Sprint 42?"

Rovo invokes the analyze-workprint action, synthesizes live metrics, and outputs a direct link to the full report.

Category 05

Security, Privacy & Personal Data

Where is our data stored?

Nowhere outside Atlassian Cloud. In accordance with our official Personal Data Declaration, Workprint does not maintain any external databases or servers. All data processing occurs in-memory during function execution in Atlassian Forge's Node.js 22 sandbox. Zero personal data or user identifiers are copied, stored, or cached beyond 24 hours.

Is Workprint GDPR and CCPA compliant?

Yes. Because Workprint queries live Atlassian REST APIs on-demand without keeping persistent replicas, user profile updates, deletions, and anonymizations made in Atlassian Admin are immediately reflected. End-users can export their complete capacity profile via the built-in CSV export button at any time.

Category 06

Capacity Calculations & Metrics

How is capacity percentage calculated?

Capacity percentage is based on a standard 40.0-hour engineering sprint week. Workprint aggregates recorded time spent and estimated remaining hours from Jira issues, estimates 2.5 hours per open Bitbucket PR review, and 2.0 hours per active Confluence specification under authoring. If total logged hours reach 38.0h, the engineer is marked as In Focus (95% Load).

How does the "Reassign Workload" feature work?

Workprint provides a direct modal to reassign overloaded Jira tickets to available teammates. When confirmed, Workprint calls Jira Cloud REST API v3 (PUT /rest/api/3/issue/{issueKey}/assignee) via api.asApp() with the write:jira-work scope, updating the issue in real time.
