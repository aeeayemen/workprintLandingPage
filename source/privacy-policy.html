1. Overview & Cloud Architecture

This Privacy Policy applies to the Workprint application for Jira, Confluence, and Bitbucket (including the Workprint Capacity Agent for Atlassian Rovo AI), published and maintained by Anas Adel Ismail (Yemen) for distribution across Atlassian Cloud sites.

Workprint is built natively on the Atlassian Forge serverless platform (Node.js 22 runtime). Unlike legacy plugins that run on external servers, Workprint runs entirely within Atlassian's secure cloud infrastructure. All backend resolvers and telemetry aggregations execute inside ephemeral sandbox functions managed directly by Atlassian.

Architecture Summary: Workprint maintains zero external application servers and zero external databases. Data is retrieved on-demand via official Atlassian Forge APIs and processed purely in memory during active execution.

2. Atlassian Forge Manifest Scopes & API Usage

Workprint adheres strictly to the principle of least privilege. In order to synthesize cross-functional capacity metrics, Workprint requests only the following permissions in its manifest.yml:

Forge Scope API Execution Context Functional Justification
read:jira-work api.asApp() Queries open issues, timetracking worklogs, status categories, and priority via Jira Cloud REST API v3 (POST /rest/api/3/search/jql).
read:jira-user api.asApp() Resolves active workspace user profiles, display names, and avatars to populate the capacity directory.
read:me api.asUser() Identifies the viewing user to provide personalized deep links to their own workload report.
write:jira-work api.asApp() Powers the interactive "Reassign Workload" feature, enabling managers to balance sprint tasks by updating assignee IDs.
read:confluence-content.all
search:confluence		 api.asApp() Fetches pages actively authored or edited by the selected engineer via CQL (contributor = "accountId") to evaluate documentation load.
read:confluence-space.summary
read:confluence-user		 api.asApp() Retrieves space keys and version numbers to build valid direct links to technical documents.
storage:app api.asApp() Forge Key-Value storage declaration reserved for site-level workspace configurations (such as custom sprint hour benchmarks).

3. Bitbucket Cloud REST API & External Fetch

Workprint integrates with Bitbucket Cloud via its REST API v2 (https://api.bitbucket.org). As declared in the Forge manifest under permissions.external.fetch.backend, Workprint connects to Bitbucket to monitor pull request bottlenecks and code review turnaround time.

  • Workspace Repository Access Token: Authentication is handled at the workspace level with minimal read-only scope (read:pullrequest). Individual developers do not need to share personal credentials.
  • Targeted PR Filtering: Workprint fetches open pull requests and repository commit authors to match against the target engineer's Atlassian Account ID, nickname, or registered email.
  • Zero Source Code Inspection: Workprint does not read, parse, or download repository source code, diff contents, or proprietary algorithm files. Only PR metadata (title, author, reviewer list, creation timestamp) is inspected to calculate review lag.

4. Personal Data Declaration

In accordance with Atlassian's Developer Terms and app distribution requirements ("Start sharing your app"), the maintainer explicitly declares the following personal data handling practices:

A. Categories of Personal Data Processed:
  • Atlassian Account Identifier (accountId): Unique cryptographic string used to correlate assigned Jira tasks, Confluence pages, and Bitbucket contributions.
  • User Display Name & Profile Initial: Displayed on workload dashboard cards, CSV export summaries, and Rovo AI chat messages.
  • Work Email Address: Used solely in memory when cross-referencing Git commit author strings with Atlassian accounts.
  • Engineering Telemetry Metadata: Timetracking logs, sprint velocity counts, and PR review timestamps associated with work items.
B. Prohibition on Outside-Cloud Storage & Caching:

NO PERSONAL DATA OR USER IDENTIFIERS ARE COPIED, STORED, OR CACHED BEYOND 24 HOURS OUTSIDE ATLASSIAN CLOUD. Workprint does not transmit user identifiers, account IDs, employee names, or project keys to any external relational database, NoSQL store, analytics vendor, or third-party cloud infrastructure. All data calculations are ephemeral and reside strictly in volatile runtime memory during function invocation.

C. Third-Party Analytics, Tracking & Cookies:

Workprint contains zero third-party tracking scripts, zero advertising pixels, and zero tracking cookies. Network traffic is strictly restricted to Atlassian Cloud APIs and the declared Bitbucket Cloud endpoint.

5. Data Retention, Caching & Deletion

Because Workprint utilizes an ephemeral query model, there is no persistent user datastore to maintain or purge:

  • Zero Persistent Storage: No historical snapshots of employee capacity or task lists are persisted in app storage. When a user navigates away or closes the tab, all local report state is cleared.
  • No 24-Hour Cache Window: Workprint does not maintain a server-side cache. Every report generated is computed fresh from live product REST APIs. Consequently, no customer data is cached beyond 24 hours.
  • Instant Uninstallation Cleanup: If a customer uninstalls Workprint via the Jira / Confluence Manage Apps screen or via forge uninstall, all Forge app permissions are revoked immediately, leaving zero residual data behind.

6. Security, Isolation & Encryption

Workprint benefits from the physical, network, and operational security of the Atlassian Forge platform:

  • Tenant Isolation: Every API call and resolver execution occurs within the context of the customer's specific Atlassian site tenant. Cross-tenant data leakage is architecturally prohibited by Forge containerization.
  • Encryption in Transit: All communication between the Forge Custom UI iframe, backend resolver functions, Jira, Confluence, and Bitbucket occurs over TLS 1.3 encrypted HTTPS tunnels.
  • Strict Content Security Policy (CSP): The application enforces Atlassian CSP headers prohibiting unauthorized external script injection or egress to undeclared domains.

7. Atlassian Rovo AI Agent (workprint-rovo-agent)

Workprint exposes an intelligent Atlassian Rovo agent (workprint-rovo-agent) with the action analyze-workprint.

When a user interacts with the Workprint Capacity Agent inside Atlassian Rovo:

  • Prompt inputs (e.g. an engineer's name) are passed exclusively to the registered Forge function rovoActionHandler.
  • The output synthesizes live workload metrics, bandwidth percentages, and markdown links to the Jira global page.
  • Customer data is never transmitted to third-party model providers outside Atlassian Rovo's sanctioned AI architecture. Workprint does not train AI models on customer data.

8. Data Subject Rights (GDPR & CCPA)

Under the General Data Protection Regulation (GDPR), the California Consumer Privacy Act (CCPA), and similar global regulations, end-users have rights regarding their personal data:

  • Right of Access & Portability: Users can inspect their complete capacity profile directly in the Workprint dashboard or export it as a standard CSV report via the "Export CSV" action.
  • Right to Rectification: Because Workprint displays live data from Jira and Confluence, any correction made to an Atlassian account or issue in Jira is instantly reflected in Workprint.
  • Right to Erasure ("Right to be Forgotten"): When an Atlassian account is deleted or anonymized by an Atlassian administrator, Workprint no longer resolves or displays any records for that account ID.
